# Submission validation (#54)

`POST /api/v1/order-drafts/:id/validate` accepts exactly `{version}` as JSON for an authenticated active Customer Admin/User and their own editable draft. It returns the standard no-store envelope with `{draftVersion,valid,issues}`. Each issue has a code and, for a line issue, its portal item ID. This is an immediate preflight result, not a reservation, snapshot, submission, idempotency key or permission to submit later. #62 must invoke equivalent live checks at the actual submission boundary and handle the remaining race with the authoritative system; #55–#57 own change presentation, snapshots and idempotency.

The service rechecks session, company, creator, draft state and version before and after the live request. It validates current active/eligible customer and product, selling UOM, positive draft quantity and MOQ, effective customer/default price, known sufficient stock, active same-company delivery address, and exact order value against the configured minimum. Unknown stock blocks. No floating point, implicit currency conversion, rounding, or inferred UOM increments are used. A missing price, currency mismatch or invalid source prevents a successful validation. Source failures and missing setup return the existing unavailable error; a changed draft or reference context returns conflict. Client policy, price, stock and ERP references are never accepted or returned.

Configure both `SUBMISSION_MINIMUM_AMOUNT` and `SUBMISSION_MINIMUM_CURRENCY` in the server environment. Amount must be a nonnegative canonical decimal with at most 24 integer and 18 fractional digits; currency must be three uppercase letters. Both omitted leaves validation unavailable, not disabled. Partial or malformed settings cause a redacted startup configuration error. Set `ERP_BASE_URL` and `ERP_TIMEOUT_MS` to the existing Mock ERP service; the request-time source reads its no-store `master-data` and paged `catalog` endpoints and resolves applicable customer price before default price using their effective windows. It does not use synchronized catalog prices or inventory as authority.

The only implemented provider is the explicitly synthetic fixed Mock ERP source, enabled for development/test only; production validation remains unavailable until a real authoritative provider is implemented. A live read is not a stock reservation and can become stale immediately. ERP references are server-derived and remain private. Validation does not change order state or call an ERP submission endpoint.
